# 2週間試験チェックリスト

**目的**: 利益最大化ではなく、**環境判定・STOP・記録・ルール遵守** が本番に耐えるか確認する。

| 項目 | 試験設定 |
|------|----------|
| ロット | 0.0001 BTC |
| トラリピ幅 | 50,000円 |
| 買い本数（フル） | 8本 |
| 資金目安 | JPY 3〜5万円 |
| 日次損失上限 | -2,000円（本番時） |
| 週次損失上限 | -5,000円 → 1週間 DRY_RUN に戻す |

---

## フェーズ概要

| 期間 | フェーズ | DRY_RUN | 主な目的 |
|------|----------|---------|----------|
| **Day 1〜3** | セットアップ | `true` | シート・トリガー・LINE・ログの正常性 |
| **Day 4〜10** | 観察 | `true` | 環境切替頻度・判定精度・STOP 動作 |
| **Day 11〜14** | 判断 | `true` → 条件付き `false` | 本番移行可否の Go / No-Go |

---

## Week 1 — DRY_RUN 観察（Day 1〜7）

### Day 1（月）

- [ ] 運用ログが 5 分ごとに増えている（288行/日は多すぎ注意→正常なら OK）
- [ ] tradePulse の LINE が **環境変化時のみ**（売買では来ない）
- [ ] 日次集計 1 行目を記入（フェーズ=DRY_RUN）
- [ ] 手動で bitbank 注文していない（ルール遵守 OK）

### Day 2

- [ ] GAS 実行エラーなし（Apps Script → 実行数 → 失敗 0）
- [ ] 運用ログの ADX / ER に値が入っている
- [ ] 環境ラベル（レンジ/中立/トレンド等）が妥当か日次集計 P 列にメモ

### Day 3

- [ ] `bbShowLog` または Apps Script ログで ERROR なし
- [ ] tradePulse と GAS の BTC 環境が **完全一致しなくてもよい** が、大きく矛盾していないか確認
- [ ] 週次中間: 環境切替回数/日の平均をメモ（目安 0〜3）

### Day 4

- [ ] レンジ判定時 → 操作が「トラリピ（フル）」になっている（DRY_RUN ログ）
- [ ] 中立判定時 → 「トラリピ（縮小）」

### Day 5

- [ ] トレンド判定時 → 「スイング」＋ アップ/ダウン表示（LINE or ログ）
- [ ] トレンド（ダウン）時に無理に買っていない（現物ロングのみ設計）

### Day 6

- [ ] 急変（1H ±1.5% 以上）があれば STOP ログを確認  
      ※ なければ「未発生」で OK、発生時は必須チェック
- [ ] STOP 時: `[DRY_RUN] cancel` または キャンセル件数ログ

### Day 7（Week 1 レビュー）

- [ ] 日次集計 7 行完成
- [ ] 環境精度: ◎+△ が **5日以上 / 7日**
- [ ] ルール遵守 NG = **0**
- [ ] 設定変更（ロット・幅・DRY_RUN）していない
- [ ] Week 1 総合: **合格 / 要改善 / 中止** を 2週間試験シートに記入

**Week 1 不合格の場合**: Day 8 以降も DRY_RUN 継続。閾値変更は **1項目のみ**、変更理由を U 列に記録。

## Go / No-Go 判定表（Day 11 または Day 14）

| # | 条件 | 必須 |
|---|------|------|
| 1 | DRY_RUN で 10 日以上、GAS 実行失敗が **週 1 回未満** | ✓ |
| 2 | 急変 STOP がログ上 **動作確認済み**（発生時）または 1H 急変未発生を記録 | ✓ |
| 3 | ルール遵守 NG = **0**（手動介入・設定変更なし） | ✓ |
| 4 | 環境精度 ◎+△ が **全体の 70% 以上** | ✓ |
| 5 | 日次集計が **10 日分以上** 埋まっている | ✓ |
| 6 | tradePulse LINE が環境変化のみ（売買通知なし） | ✓ |
| 7 | 週次損失 -5,000円 超えていない（本番移行後のみ） | 本番時 |

**Go（本番移行可）**: 必須 1〜6 すべて ✓  
**条件付き Go**: 5 だけ未達 → Day 14 まで DRY_RUN 延長  
**No-Go**: 3 または 4 が未達 → 設定見直し後、**新たに 2 週間** やり直し

## トラブル時の即時対応

| 現象 | 対応 |
|------|------|
| GAS ERROR 連発 | トリガー停止 → `bbShowLog` 確認 → DRY_RUN=true |
| 想定外の注文残り | bitbank アプリで全キャンセル → DRY_RUN=true |
| 日次 -2,000円 超 | その日手動 STOP、翌日まで新規なし |
| 週次 -5,000円 超 | DRY_RUN=true に戻し、2 週間再試験 |
| LINE 洪水 | tradePulse / GAS の `lastLineRegime` 確認、環境チラつき調査 |

## 2週間試験シート（スプレッドシート内）の使い方

メニュー **6. シート初期化** で「2週間試験」タブが作成されます。

- **A列**: チェック項目
- **B列**: Day 1〜14（✓ を入力）
- **C列**: 完了日
- **D列**: メモ

最終行に **Week1 判定 / Week2 判定 / Go-No-Go** 欄があります。
